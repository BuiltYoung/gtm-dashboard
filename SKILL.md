# GTM Dashboard

Made by Built Young (builtyoung.org). This credit is for people reading the skill.

Numbers don't say a team is failing. They say where to fix. This skill sets up the smallest tracking that works, then turns each week's log into one decision. Built for Built Young classes and for any first-time founder.

It has two jobs. Pick by what the user brings: nothing yet means **Set up**; a log means **Read**.

## Set up

1. **Define the funnel for this product.** Three steps, each a thing a person does:
   - **Visit:** opened the page (from the page's analytics or the link tracker)
   - **Sign-up:** joined the waitlist or made an account
   - **Active:** did the one action that means they got value (made a quiz, added a club member, came back twice). Ask the team to name it.
   - Add **Paid or pre-ordered** only if the product charges.
   - **Say what one sign-up is:** a person, or an organisation (a club, a class, a school). Count that same unit at every step and write it at the top of the log. When an organisation signs up and its people then use the product, keep two separate lines (clubs signed up and clubs active; members active) and never divide one by the other.
2. **One tracked link per channel** (the landing-waitlist skill makes them).
3. **The daily log**, five minutes a day, one row per channel:

```
Date | Channel | What we posted or did | Visits | Sign-ups | Active | Notes
```

4. **Say where each number comes from** for this team's tools, and who fills the log in.

Followers, likes and views go in Notes. They are not the funnel; a post can get many views and no sign-ups.

## Read

### 1. Take the log

A pasted table, a spreadsheet or CSV, or numbers read from screenshots. State the dates it covers and list any missing days. Never fill a gap. State the unit being counted (people or organisations). If the log doesn't say, or mixes the two, ask before working out any rate.

### 2. Do the arithmetic

Use a code tool when one is available, so the sums are exact. Show:

- **By channel:** visits, sign-ups, sign-up rate (sign-ups ÷ visits), active, and the change from the week before when there is one
- **The funnel overall:** visits → sign-ups → active, with the share that continues at each step
- **Best post or action per channel**, by sign-ups

### 3. Find the leak

| What the numbers show | The problem is probably | One change to try |
|---|---|---|
| Few visits | The channel or the content | A different hook, more posts, or swap the channel |
| Visits but few sign-ups | The page | Rewrite the headline, move the button up, ask for less |
| Sign-ups but few active | The first experience | A welcome message, an easier first step |
| One channel converts far better | That's the team's channel | Move hours to it from the weakest one |

Name the single biggest drop-off, then one change per channel. One change at a time, or nobody learns which one worked.

### 4. Say how sure this is

With fewer than about 100 visits or 30 sign-ups on a channel, call the result an early signal and say what would confirm it. Two sign-ups versus four is not a trend.

### 5. Deliver

1. The channel table and the funnel
2. One sentence the team says aloud: "Our biggest drop-off is ___, we'll fix it by ___, and we'll know it worked if ___."
3. A weekly update, five lines, for the team's Slack or class
4. A traction line for a pitch deck, with dates and the real numbers: "61 sign-ups in 3 weeks from 3 channels; 38% came from school clubs."
5. Next week's empty log

When asked for a file, give the log and the tables as a spreadsheet, or a one-page chart.

End with **For the run record:** `Numbers to [date]: [visits / sign-ups / active] · best channel: [...] · this week's change: [...]`.

## Rules

- Only numbers from the log. No estimates, no smoothing, no carrying last week's figures forward.
- No projections ("on track for 10,000 users"). Say what happened and what will be tried.
- A traction line states the period and the source, and never rounds up.
- Every count carries its unit: "44 active clubs" or "44 active members", never "44 active".
- The log holds counts, not people. No names, emails or usernames of users in a dashboard.
- A bad week is reported as plainly as a good one.

## Class mode

For several teams, return each team's table and its one sentence, and a single line comparing which kind of channel worked best across the class.
